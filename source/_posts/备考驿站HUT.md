## 先做资料详情页，按「能演示的完整主流程」来做。
```
- git add app.json：把这个文件的改动放进"待提交区"
- git commit -m "..."：正式存档，引号里是这次改动的说明
```
1. 先看范例：列表页当初的说明书长这样

用你已经熟悉的列表页反推，大概就是：

▎ 资料列表页说明书
▎ ① 背景：学生打开小程序看到的第一页，用来浏览、找备考资料。
▎ ② 元素：从上到下依次是——搜索框（先只做样子）、分类标签栏（可横向滑）、资料卡片列表（每张卡：标题、积分/免费角标、分类、学院、上传者、评分、下载次数）、底部一行说明文字。
▎ ③ 数据：卡片上显示上面列的字段，目前是 8 条假数据。
▎ ④ 来源：假数据先写死在 JS 文件里，以后换成云数据库读取。
▎ ⑤ 交互：点分类标签 → 筛选；点卡片 → 进详情页（还没做，先弹提示）；点搜索框 → 去搜索页（还没做，先弹提示）。
▎ ⑥ 边界：某分类下一份资料都没有 → 显示"成为第一个上传的人吧"。

看出来了吗——每项就一两句话，一个技术词都没有，全是产品想法。你按这个浓度写就行。

2. 填空模板：把下划线换成你的想法

① 背景：用户从____进入本页，想干____。

② 元素：从上到下依次是____。
（提示：详情页常见的有——大标题、上传者信息、简介、文件信息（格式/大小/页数）、
下载按钮、收藏、评分、同类资料推荐……你挑想要的，也可以加别的，也可以砍）

③ 数据：每个元素上显示什么？
（提示：列表页已有的 title / college / uploader / rating / downloads / points
要接得上；再想想要补什么新字段）

④ 来源：页面怎么知道用户点的是哪份资料？
（这题不用答得"技术上正确"，说出你的直觉就行，实现方式我来选）

⑤ 交互：点下载→____；点收藏→____；点评分→____；
其他按钮→____
（现在没后端，可以先弹提示，但请把"将来真做出来时该发生什么"写上）

⑥ 边界：什么意外情况会出现，页面怎么应对？
（提示：资料被删了？积分不够？没登录？网络挂了？）
- 页面用途：4 条全要——看简介判断值不值、直接下载、看评分评价、收藏备用
- 版面：基础款（标题 / 上传者 / 下载收藏按钮）之外，加四块——简介、文件信息、评分与评价区、同类资料推荐
- 下载行为：按积分标记走——免费的直接下，带积分标记的扣积分
- 积分不足：弹提示 + 引导去赚积分（打卡 / 上传）
- 登录检查：演示阶段先都不检查
- 评价区：用户能打分 + 写评论（现在先弹提示）
- 资料下架：页内显示「已下架」提示
- 数据怎么传（你交给我定的，我选了）：列表只把资料编号（id）传给详情页，详情页拿编号去「资料库」里查。理由：以后换成云数据库只改"查库"这一步，而且"查无此资料"天然就能触发你要的"已下架"显示。

1. 需求说明书：六项框架（今天的主课）

- 知道了 背景 / 元素 / 数据 / 来源 / 交互 / 边界 每一项该写什么、写到什么浓度（大白话、一两句）
- 背景写错过一次：第一版写成了列表页的背景（"打开小程序进入本页"）——详情页是第二层，要写"从哪来、想干嘛"
- 完整性是审出来的：你采访里选了"看评价"，但 ② 里漏了评价区，被看出来补上了
- 一致性也是审出来的：定稿前你抓掉了两处自相矛盾（"按钮上写积分" vs "页面不展示积分"、评分放标题旁还是评价区）——这种矛盾留到代码里就是 bug
- 边界思维：积分不足 / 资料下架 / 暂无评价——主动想"什么情况会出错"，这是新手和熟手的分水岭
- 还学了一招：写不出来时，先被采访再整理——你用选择题把想法一题题挖出来，最后自己组织成文

2. AI 协作开发的工作流（今天完整跑通第一遍）

▎ 说明书 → AI 写代码 → 人逐项验收 → 提交

你的岗位是需求表达 + 验收，我的岗位是实现。验收不是"看一眼差不多"，是拿着说明书一项一项对（今天 16 项逐个过）。后半程你写的 ③⑤⑥ 明显比 ① 通顺得多——这就是练出来的。

3. git 基本功

- add（放进待提交区）和 commit（存档）两步各是什么，为什么动代码前先存档
- 读 git log 看历史；今天你自己完成了 2 笔提交，还会"改完再补一笔提交"的节奏

4. 微信开发者工具

- 编译模式：给页面配参数（id=999）直达任意页面，不用每次从首页点进去——调试和演示边界的利器，以后天天用
- 在项目文件树里新建、编辑文件，Cmd+S 保存

5. 终端小技能

- mkdir -p（建文件夹）、touch（建空文件）

6. 两个架构意识（你验收点头的那几项）

- 数据放公共文件（utils/materials.js）：两个页面共用一套数据，以后换真数据库只改一个地方
- DEMO_USER.points 一个数字切换演示效果——原型阶段的"假数据"就是这么玩的

一句话：今天你练的不是敲代码，而是 AI 编程里更值钱的三件事——把需求说清楚、把结果验仔细、把过程管住。
